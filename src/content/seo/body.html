Google কীভাবে ওয়েবসাইট খুঁজে পায় ও Index করে

Google-এর কাজ তিনটি প্রধান ধাপে: Crawling → Indexing → Serving / Ranking।

Crawling

Googlebot ওয়েবপেজ খুঁজে বের করে এবং পেজের কনটেন্ট সংগ্রহ করে।

Indexing

কনটেন্ট ও অন্যান্য সংকেত বিশ্লেষণ করে, উপযুক্ত হলে নিজের Index-এ সংরক্ষণ করে।

Ranking

কেউ সার্চ করলে প্রাসঙ্গিক ফলাফল নির্বাচন করে সাজিয়ে দেখায়।

১. Crawling কী?

ধরুন webspacedev.com-এ এই পেজগুলো আছে: /, /services/web-development, /services/ecommerce, /portfolio। Googlebot অন্য পেজের লিংক এবং XML sitemap থেকে URL-গুলো খুঁজে পায়, তারপর অ্যাক্সেসযোগ্য পেজ crawl করার চেষ্টা করে।

Developer হিসেবে করণীয়:

  • পেজে সঠিক HTTP response (200) দিন।
  • গুরুত্বপূর্ণ পেজে noindex রাখবেন না।
  • robots.txt দিয়ে ভুল করে প্রয়োজনীয় পেজ ব্লক করবেন না।
  • পেজগুলোর মধ্যে কাজের উপযোগী internal links রাখুন।
  • XML sitemap তৈরি করুন।

২. Indexing কী?

Crawl হলেই পেজ index হবে, এমন নয়। Google মূল কনটেন্ট, canonical URL, duplicate content, noindex নির্দেশনা ইত্যাদি দেখে সিদ্ধান্ত নেয়। Index হওয়া মানে কেবল সার্চে দেখানোর যোগ্য হওয়া — প্রথম পেজে থাকা নয়।

৩. Ranking কী?

কেউ “web development company in Bangladesh” সার্চ করলে Google অনেক পেজের মধ্যে কোনটি বেশি প্রাসঙ্গিক ও উপকারী তা মূল্যায়ন করে। গুরুত্বপূর্ণ বিষয়:

  • Search intent-এর সঙ্গে কনটেন্টের মিল
  • কনটেন্টের উপযোগিতা ও নির্ভরযোগ্যতা
  • পেজের অ্যাক্সেসযোগ্যতা ও ব্যবহারকারীর অভিজ্ঞতা
  • ওয়েবসাইট সম্পর্কে প্রাসঙ্গিক অন্যান্য সংকেত

ভুল ধারণা: শুধু বেশি keyword ব্যবহার করলে ভালো ranking নিশ্চিত হয় না।

robots.txt, XML Sitemap ও Canonical

তিনটির কাজ আলাদা:

/robots.txt

কোন URL crawl করা যাবে?

Crawler-কে path-এর অনুমতি/সীমাবদ্ধতা জানায়। পাসওয়ার্ডের বিকল্প নয়, index থেকে সরানোর নিশ্চয়তাও দেয় না।

/sitemap.xml

কোন পেজ গুরুত্বপূর্ণ?

Index-যোগ্য URL Google-কে আবিষ্কারে সাহায্য করে। জমা দিলেই index নিশ্চিত নয়।

rel=canonical

কোন URL মূল সংস্করণ?

একই/কাছাকাছি কনটেন্টের একাধিক URL থাকলে preferred URL-এর সংকেত দেয়।

১. robots.txt তৈরি করুন

app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: ['/api/'],
    },
    sitemap: 'https://webspacedev.com/sitemap.xml',
  }
}

সতর্কতা: /api/ উদাহরণটি নিজের URL কাঠামো অনুযায়ী বদলাবেন। ভুল নিয়মে public page, CSS বা JS ব্লক করবেন না। Disallow করলেই URL index হবে না — এমন নিশ্চয়তা নেই।

২. XML Sitemap তৈরি করুন

app/sitemap.ts
import type { MetadataRoute } from 'next'

const siteUrl = 'https://webspacedev.com'

export default function sitemap(): MetadataRoute.Sitemap {
  const pages = [
    '/',
    '/services/web-development',
    '/services/ecommerce',
    '/portfolio',
    '/contact',
  ]

  return pages.map((path) => ({
    url: `${siteUrl}${path}`,
    lastModified: new Date(),
  }))
}

বাস্তব প্রজেক্টে lastModified-এ প্রতিটি পেজের প্রকৃত শেষ পরিবর্তনের তারিখ দিন; প্রতি build-এ তারিখ বদলানো মিথ্যা আপডেট-সংকেত। হাজার হাজার dynamic page থাকলে sitemap ভাগ করুন বা ডেটাবেস থেকে URL তৈরি করুন।

Next.js Metadata API

Metadata হলো HTML <head>-এর তথ্য, যা সার্চ ইঞ্জিন ও social sharing-এ কাজে লাগে। App Router-এ দুইভাবে সেট করা যায়:

  • metadata — স্থির পেজের জন্য।
  • generateMetadata() — database বা API থেকে আসা dynamic content-এর জন্য।
app/portfolio/[slug]/page.tsx
import type { Metadata } from 'next'

type Props = {
  params: Promise<{ slug: string }>
}

export async function generateMetadata(
  { params }: Props,
): Promise<Metadata> {
  const { slug } = await params

  // বাস্তবে এখানে database/API থেকে project আনবেন
  const project = {
    title: 'Ecommerce Website',
    description: 'A custom ecommerce website project.',
  }

  return {
    title: project.title,
    description: project.description,
    alternates: {
      canonical: `/portfolio/${slug}`,
    },
  }
}

export default function PortfolioPage() {
  return <main><h1>Portfolio Project</h1></main>
}

Production-এ slug অনুযায়ী আসল project fetch করবেন এবং না পেলে notFound() ব্যবহার করবেন।

SEO টিপ: প্রতিটি গুরুত্বপূর্ণ পেজের title ও description আলাদা এবং আসল content-এর সঙ্গে মিল থাকা উচিত। একই metadata সব পেজে কপি করবেন না।

নিজের পেজে কী পরীক্ষা করবেন

  1. Browser-এ পেজ খুলে View Page Source দেখুন।
  2. গুরুত্বপূর্ণ heading ও content প্রাথমিক HTML-এ আছে কি না নিশ্চিত করুন।
  3. Search Console-এর URL Inspection দিয়ে Google-এর দেখা পেজ পরীক্ষা করুন।
  4. প্রয়োজনে Live Test চালিয়ে rendering যাচাই করুন।

মনে রাখুন: JavaScript ব্যবহার নিজে SEO সমস্যা নয়। সমস্যা হয় যখন গুরুত্বপূর্ণ content বা links crawler-এর কাছে পৌঁছায় না।

Core Web Vitals ও Mobile Performance

বাস্তব ব্যবহারকারীর loading, responsiveness ও visual stability মাপার তিনটি metric। সাধারণত ৭৫তম percentile ডেটা দিয়ে মূল্যায়ন হয়।

INP · Interaction to Next Paint≤ 200 ms

CLS · Cumulative Layout Shift≤ 0.1

লোডের সময় উপাদান কতটা সরে যায়। উন্নতি: ছবির width/height, dynamic content-এর জায়গা, font loading।

Google Business Profile ও Local SEO

Local SEO-এর মাধ্যমে নির্দিষ্ট এলাকার মানুষ আপনার ব্যবসা, যোগাযোগের তথ্য ও Google Maps ফলাফল খুঁজে পান। তবে প্রতিটি অনলাইন এজেন্সি Google Business Profile-এর যোগ্য নয়।

Google-এর নিয়মে ব্যবসাকে গ্রাহকের সঙ্গে সরাসরি যোগাযোগ করতে হয় — গ্রাহকের কাছে গিয়ে সেবা দেওয়া বা বাস্তব অবস্থানে গ্রাহককে সেবা দেওয়া। শুধু অনলাইনে কাজ করা ব্যবসা সাধারণত যোগ্য নয়।

যোগ্য হলে করণীয়

  • Google Business Profile-এ ব্যবসা যোগ করুন বা বিদ্যমান প্রোফাইল দাবি করুন।
  • বাস্তব ব্যবসার নাম ব্যবহার করুন।
  • সঠিক category, phone, website ও প্রযোজ্য service area দিন।
  • প্রোফাইল verification সম্পন্ন করুন।
  • প্রকৃত গ্রাহকের honest review নিন ও উত্তর দিন।
  • তথ্য বদলালে নিয়মিত আপডেট করুন।

বাসা থেকে পরিচালিত service-area business হলে service-area setup প্রযোজ্য হতে পারে; গ্রাহক গ্রহণের অফিস না থাকলে বাড়ির ঠিকানা জনসমক্ষে দেখাতে হয় না।

Online-only হলে: জোর করে listing না বানিয়ে organic SEO, portfolio, ওয়েবসাইট এবং প্রাসঙ্গিক industry directory-তে মনোযোগ দিন।

রেফারেন্স: OpenAI web crawlers documentation

app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      { userAgent: '*', allow: '/' },
      { userAgent: 'OAI-SearchBot', allow: '/' },
      { userAgent: 'GPTBot', disallow: '/' },
    ],
    sitemap: 'https://webspacedev.com/sitemap.xml',
  }
}

এখানে সাধারণ crawler ও OAI-SearchBot অনুমতি পেয়েছে, GPTBot নিষেধ। GPTBot-কে অনুমতি দিতে চাইলে আপনার নীতি অনুযায়ী rule বদলাবেন। বিদ্যমান robots.ts-এর rule না বুঝে প্রতিস্থাপন করবেন না।

আরও যাচাই করুন

  • https://webspacedev.com/robots.txt সঠিকভাবে খুলছে।
  • Cloudflare, WAF বা server firewall অনিচ্ছাকৃতভাবে crawler ব্লক করছে না।
  • গুরুত্বপূর্ণ পেজে noindex নেই এবং পেজগুলো public।

মনে রাখুন: OAI-SearchBot অনুমতি দিলেই ChatGPT আপনাকে উল্লেখ করবে — এমন নিশ্চয়তা নেই। robots.txt security mechanism নয়; গোপন তথ্যের জন্য authentication লাগবে।

Structured Data ও Organization / Service Schema

Structured data হলো পেজের তথ্য নির্দিষ্ট format-এ সাজিয়ে সার্চ ইঞ্জিনকে বোঝানো — সাধারণত Schema.org vocabulary ও JSON-LD format।

Organization schema

app/components/organization-schema.tsx
const schema = {
  '@context': 'https://schema.org',
  '@type': 'Organization',
  name: 'Web Space Dev',
  url: 'https://webspacedev.com',
  logo: 'https://webspacedev.com/logo.png',
  description:
    'Web development and digital solutions for businesses.',
}

export default function OrganizationSchema() {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify(schema).replace(/</g, '\\u003c'),
      }}
    />
  )
}
app/layout.tsx
import OrganizationSchema from './components/organization-schema'

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en">
      <body>
        <OrganizationSchema />
        {children}
      </body>
    </html>
  )
}

Business name, URL ও logo প্রকৃত তথ্য দিয়ে বদলাবেন। সাইটে নেই বা বাস্তবের সঙ্গে মেলে না — এমন তথ্য JSON-LD-তে দেবেন না।

AI-সহায়ক Content Strategy

AI দিয়ে content বানানো যায়, কিন্তু অনেক AI-generated article প্রকাশ করাই SEO strategy নয়। লক্ষ্য: ব্যবহারকারীর জন্য উপকারী, নির্ভরযোগ্য, নিজস্ব মূল্য যোগ করা content।

উদাহরণ: “How Much Does an Ecommerce Website Cost in Bangladesh?”

  1. সংক্ষিপ্ত উত্তর: খরচ কোন কোন বিষয়ের ওপর নির্ভর করে।
  2. Website type: basic store, custom ecommerce, complex platform।
  3. খরচের উপাদান: design, development, payment integration, hosting, maintenance।
  4. বাস্তব project experience বা উদাহরণ।
  5. কোন ব্যবসার জন্য কোন সমাধান উপযুক্ত।
  6. Frequently asked questions।
  7. পাঠক কীভাবে project inquiry করবেন।

সতর্কতা: নির্ভরযোগ্য মূল্যতথ্য না থাকলে কাল্পনিক market price দেবেন না। নিজের package থাকলে সেটা পরিষ্কার ব্যাখ্যা করুন।

AI ব্যবহারের workflow

Research

Search Console query, customer প্রশ্ন, competitor gap।

Outline

AI দিয়ে প্রশ্নের উত্তরভিত্তিক কাঠামো।

Human expertise

নিজের অভিজ্ঞতা, project data, screenshot, যাচাই করা তথ্য।

Publish ও review

Title, metadata, internal links, sources, accuracy যাচাই।

AI Search-এ উদ্ধৃত হওয়ার সম্ভাবনা বাড়াতে

  • প্রশ্নের উত্তর সরাসরি ও পরিষ্কার ভাষায় দিন।
  • নিজের বাস্তব অভিজ্ঞতা ও নির্দিষ্ট উদাহরণ দিন।
  • গুরুত্বপূর্ণ claims-এর পাশে নির্ভরযোগ্য sources দিন।
  • Company name, services, project details ও contact তথ্যে সামঞ্জস্য রাখুন।
  • প্রাসঙ্গিক পেজ internal links দিয়ে সংযুক্ত করুন।
  • AI নয়, বাস্তব পাঠকের প্রয়োজনকে প্রাধান্য দিন।

বাস্তবতা: llms.txt বা প্রতিটি paragraph ছোট টুকরো করা AI ranking-এর নিশ্চিত কৌশল নয়। আগে crawlability, ভালো content ও SEO-এর ভিত্তি ঠিক করুন।

Search Console দিয়ে ফলাফল পরিমাপ

Impressions

Google Search-এ সাইট কতবার দেখানো হয়েছে।

Clicks

Google থেকে কতবার মানুষ সাইটে এসেছে।

CTR

Impression-এর কত শতাংশ click হয়েছে।

Average Position

সার্চে ফলাফলের গড় অবস্থান।

CTR সূত্র
CTR = (Clicks ÷ Impressions) × 100%

উদাহরণ: 100 ÷ 2,000 × 100% = 5%
Metricউদাহরণ ফলাফল
Impressions2,000
Clicks100
CTR5%
Average position8.5

এগুলো উদাহরণ সংখ্যা, আপনার সাইটের বাস্তব ডেটা নয়।

Search Console কীভাবে ব্যবহার করবেন

  1. Performance → Search results: clicks, impressions, CTR, position দেখুন; আগের সময়ের সঙ্গে তুলনা করুন।
  2. Queries tab: বেশি impression কিন্তু কম CTR-এর query খুঁজুন; title ও intent পরীক্ষা করুন।
  3. Pages tab: যে service page প্রত্যাশিত ফল দিচ্ছে না, তার content, internal links ও indexing দেখুন।
  4. Indexing report ও URL Inspection: গুরুত্বপূর্ণ পেজ index হয়েছে কি না ও সমস্যা কী।

AI Search traffic পরিমাপ

  • Google AI Overviews / AI Mode থেকে click সাধারণ Search performance ডেটায় আসতে পারে; আলাদা পূর্ণ breakdown আশা করবেন না।
  • ChatGPT থেকে আসা referral analytics-এ দেখুন — URL-এ utm_source=chatgpt.com থাকতে পারে।
  • Inquiry form বা যোগাযোগের সংখ্যা মাপুন — লক্ষ্য শুধু traffic নয়, ব্যবসায়িক ফলাফল।
